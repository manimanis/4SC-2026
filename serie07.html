Exercice 1 : QCM Déclarations, Types & Normes Officielles

🟢 Facile
💡 Rappel de cours : Les Tableaux 1D et les Conventions Officielles
  • Un tableau à une dimension est une structure de données statique et homogène : tous ses éléments partagent le même type.
  • Déclaration algorithmique : Un tableau se déclare obligatoirement en deux temps :
    1. Dans le T.D.N.T. : Tab = Tableau de N Type_Élément (ex: Tab = Tableau de 20 Entier).
    2. Dans le T.D.O. / T.D.O.L. : t : Tab.
  • En Python 3 : On importe obligatoirement from numpy import array et on initialise un tableau statique de taille $N$ par : t = array([0] * N) ou array([0.0] * N).
  • Passage par adresse : Tout sous-programme qui modifie le contenu d'un tableau (remplissage, permutation, tri) doit le déclarer avec le symbole @ en algorithme : Procédure Remplir(@t : Tab, n : Entier).
  • Affichage officiel : L'instruction print(t) brut est strictement interdite aux épreuves officielles. L'affichage s'effectue toujours élément par élément via une boucle indicée Pour i de 0 à n - 1 Faire.

Exercice 4 : Contrôle Qualité Industriel & Tolérance de Fabrication (Mixte Tolérance Mécanique)

🟢 Facile

Dans une usine d'usinage mécanique de haute précision, un banc de mesure optique enregistre les diamètres effectifs (en millimètres) d'un lot de $N$ pièces cylindriques ($5 \le N \le 50$).

Le cahier des charges impose un diamètre nominal de référence $D_{ref} = 25.0\text{ mm}$ avec une tolérance admissible $\Delta = 0.2\text{ mm}$. Une pièce est déclarée conforme si son diamètre $d$ vérifie :

Condition de conformité dimensionnelle :
$$|d - D_{ref}| \le \Delta \iff (D_{ref} - \Delta) \le d \le (D_{ref} + \Delta)$$

Toute pièce hors de cet intervalle $[24.8\text{ mm}, 25.2\text{ mm}]$ est classée comme rebut.

Le système informatique doit intégrer les sous-programmes suivants :

  • Une procédure Saisie_Taille(@n : Entier) qui garantit $5 \le N \le 50$.
  • Une procédure Remplir_Mesures(@t : TabReels, n : Entier) qui lit les $N$ diamètres mesurés (chaque valeur devant être strictement positive).
  • Une fonction Est_Conforme(val : Réel, ref : Réel, tol : Réel) : Booléen qui renvoie Vrai si $|val - ref| \le tol$ (en utilisant la fonction standard Abs), et Faux sinon.
  • Une procédure Filtrer_Pieces(t : TabReels, n : Entier, ref : Réel, tol : Réel, @nb_ok : Entier, @nb_rebuts : Entier) qui parcourt le tableau et dénombre simultanément les pièces conformes et les rebuts.
  • Une fonction Taux_Conformite(nb_ok : Entier, n : Entier) : Réel qui calcule et retourne le pourcentage de pièces conformes : $\frac{nb\_ok}{n} \times 100$.
  • Une procédure Afficher_Rapport_Qualite(t : TabReels, n : Entier, ref : Réel, tol : Réel) qui affiche pour chaque pièce son numéro, sa mesure, son statut ([CONFORME] ou [REBUT]), puis le taux global de conformité et une décision finale : "Lot Accepté" si le taux $\ge 80\%$, sinon "Lot Refusé".
Travail demandé :
  1. Dresser le T.D.N.T. pour le type TabReels = Tableau de 50 Réel.
  2. Rédiger l'algorithme de la fonction Est_Conforme en utilisant Abs(val - ref).
  3. Dresser le T.D.O.L. et rédiger l'algorithme de la procédure Filtrer_Pieces.
  4. Rédiger l'algorithme de la fonction Taux_Conformite et de la procédure Afficher_Rapport_Qualite.
  5. Dresser le T.D.O.G. et rédiger l'algorithme du programme principal (en fixant $ref = 25.0$ et $tol = 0.2$).
  6. Donner la solution complète en Python 3 avec numpy.
💡 Conseils méthodologiques & Indices
  • La fonction standard Abs(x) retourne la valeur absolue en algorithme (en Python, abs(x)).
  • Dans Filtrer_Pieces, initialiser nb_ok ← 0 et nb_rebuts ← 0. Pour chaque élément t[i], appeler Est_Conforme(t[i], ref, tol). Si vrai, incrémenter nb_ok, sinon incrémenter nb_rebuts.
  • Attention à la division dans Taux_Conformite : s'assurer du calcul en réel pour éviter la division entière.
Jeux d'essais à vérifier : ($N = 6, D_{ref} = 25.0, \Delta = 0.2$)
• $T = [25.05, 24.78, 25.19, 25.35, 24.95, 25.00]$
  → Pièce 1 ($25.05$) : [CONFORME] (écart $0.05 \le 0.2$)
  → Pièce 2 ($24.78$) : [REBUT] (écart $0.22 > 0.2$)
  → Pièce 3 ($25.19$) : [CONFORME] | Pièce 4 ($25.35$) : [REBUT]
  → Pièce 5 ($24.95$) : [CONFORME] | Pièce 6 ($25.00$) : [CONFORME]
  → Conformes : $4$, Rebuts : $2$ → Taux : $\mathbf{66.67\%}$ → Lot Refusé (< 80%).

Exercice 5 : Sismologie & Détection de Pics Sismiques (Mixte Détection Locale & Tableaux Parallèles)

🟠 Intermédiaire

Un observatoire géophysique enregistre les amplitudes d'ondes sismiques à l'aide d'un capteur haute fréquence. Le signal discrétisé est stocké dans un tableau $T$ de $N$ entiers strictement positifs ($3 \le N \le 50$).

En traitement de signal, un pic sismique local est défini comme une mesure située à l'indice $i$ ($1 \le i \le N - 2$) strictement supérieure à son voisin immédiat de gauche ET à son voisin immédiat de droite :

Critère de pic sismique local :
$$T[i] > T[i - 1] \quad \text{ET} \quad T[i] > T[i + 1] \quad (\text{pour } 1 \le i \le N - 2)$$

Remarque : Les deux extrémités $T[0]$ et $T[N-1]$ ne possèdent qu'un seul voisin et ne peuvent donc jamais être qualifiées de pics stricts.

On désire implémenter la solution modulaire suivante :

  • Une procédure Saisie_N(@n : Entier) pour valider $3 \le N \le 50$.
  • Une procédure Remplir_Signal(@t : TabEntiers, n : Entier) qui lit les $N$ amplitudes entières positives.
  • Une fonction Est_Pic(t : TabEntiers, i : Entier) : Booléen qui prend le tableau et un indice $i$ ($1 \le i \le N - 2$) et teste si $T[i]$ est un pic local.
  • Une fonction Compter_Pics(t : TabEntiers, n : Entier) : Entier qui calcule le nombre total de pics dans le signal.
  • Une procédure Extraire_Pics(t : TabEntiers, n : Entier, @pics : TabEntiers, @pos : TabEntiers, @nb_p : Entier) qui construit deux tableaux parallèles :
    • pics : contient les valeurs d'amplitude de chaque pic détecté.
    • pos : contient les indices respectifs $i$ où ces pics apparaissent.
    • @nb_p : retourne le nombre effectif de pics insérés dans ces deux tableaux.
  • Une procédure Afficher_Analyse_Sismique(t : TabEntiers, n : Entier) qui affiche le signal complet, puis les résultats de l'extraction (si aucun pic n'est trouvé, afficher "Signal plat : aucun pic sismique détecté.").
Travail demandé :
  1. Pourquoi la boucle de détection des pics doit-elle obligatoirement commencer à l'indice $i = 1$ et s'arrêter à l'indice $i = N - 2$ ? Que se passerait-il si l'on évaluait Est_Pic(t, 0) ou Est_Pic(t, N - 1) ?
  2. Dresser le T.D.N.T. pour TabEntiers = Tableau de 50 Entier.
  3. Rédiger l'algorithme de la fonction Est_Pic(t : TabEntiers, i : Entier) : Booléen.
  4. Rédiger l'algorithme de la fonction Compter_Pics.
  5. Dresser le T.D.O.L. et rédiger l'algorithme de la procédure Extraire_Pics.
  6. Rédiger l'algorithme de la procédure Afficher_Analyse_Sismique.
  7. Traduire l'ensemble en Python 3.
💡 Conseils méthodologiques & Indices
  • Pour éviter un dépassement d'indice (IndexError), la condition $1 \le i \le N - 2$ garantit que $i - 1 \ge 0$ et $i + 1 \le N - 1$.
  • Dans Extraire_Pics, maintenir un curseur nb_p ← 0. Pour chaque $i$ de $1$ à $n - 2$, si Est_Pic(t, i) est vrai, affecter pics[nb_p] ← t[i], pos[nb_p] ← i, puis incrémenter nb_p ← nb_p + 1.
  • En Python, initialiser pics = array([0] * 50) et pos = array([0] * 50).
Jeux d'essais à vérifier : ($N = 8$)
• $T = [10, 45, 20, 20, 85, 30, 95, 40]$
  → Indice 1 ($45$) : $45 > 10$ et $45 > 20$ → PIC détecté à pos = 1
  → Indice 2 ($20$) : $20 \ngtr 45$ → Non pic
  → Indice 4 ($85$) : $85 > 20$ et $85 > 30$ → PIC détecté à pos = 4
  → Indice 6 ($95$) : $95 > 30$ et $95 > 40$ → PIC détecté à pos = 6
  → Nombre total de pics : 3

Exercice 6 : Cryptographie & Transformations d'un Vecteur (Mixte Permutations In-Place)

🟠 Intermédiaire

Dans un protocole expérimental de chiffrement par transposition, un bloc de données est représenté par un tableau $T$ de $N$ entiers ($4 \le N \le 40$), avec $N$ obligatoirement pair.

Pour rendre les données méconnaissables avant transmission, le vecteur subit une cascade de transformations géométriques sur place (in-place, sans tableau auxiliaire) :

  1. Inversion miroir : Échange des éléments symétriques ($T[0] \leftrightarrow T[N-1]$, $T[1] \leftrightarrow T[N-2]$, etc.).
  2. Permutation circulaire droite : Chaque élément avance d'une case vers la droite ($T[i] \to T[i+1]$), et le dernier élément revient en première case ($T[N-1] \to T[0]$).
  3. Échange des deux moitiés : La première moitié du tableau ($0 \dots \frac{N}{2}-1$) est permutée avec la seconde moitié ($\frac{N}{2} \dots N-1$).

On demande de modulariser la solution comme suit :

  • Une procédure Saisie_Taille_Paire(@n : Entier) qui exige que $N \in [4, 40]$ et que $N \text{ Mod } 2 = 0$.
  • Une procédure Remplir_Vecteur(@t : Tab, n : Entier) pour saisir les $N$ valeurs.
  • Une procédure élémentaire Permuter_Cases(@t : Tab, i : Entier, j : Entier) qui échange les valeurs de $T[i]$ et $T[j]$.
  • Une procédure Inverser_Miroir(@t : Tab, n : Entier) qui inverse le tableau sur place en effectuant une boucle Pour i de 0 à (n Div 2) - 1 et en appelant Permuter_Cases(t, i, n - 1 - i).
  • Une procédure Rotation_Droite(@t : Tab, n : Entier) qui sauvegarde le dernier élément $T[N-1]$ dans une variable temporaire, décale tous les éléments vers la droite de $N-2$ à $0$, puis place la sauvegarde en $T[0]$.
  • Une procédure Echanger_Moities(@t : Tab, n : Entier) qui échange chaque case $i$ ($0 \le i < \frac{N}{2}$) avec la case $i + \frac{N}{2}$ correspondante.
  • Une procédure Afficher_Vecteur(t : Tab, n : Entier, titre : Chaîne) qui affiche le titre et le contenu du tableau sur une seule ligne.
Travail demandé :
  1. Pourquoi la boucle de Inverser_Miroir doit-elle impérativement s'arrêter à (n Div 2) - 1 ? Que se passerait-il si elle continuait jusqu'à $n - 1$ ?
  2. Dresser le T.D.N.T. pour Tab = Tableau de 40 Entier.
  3. Rédiger l'algorithme de Permuter_Cases et de Inverser_Miroir.
  4. Rédiger l'algorithme de Rotation_Droite en détaillant le sens de parcours du décalage (pourquoi doit-on décaler de droite à gauche et non de gauche à droite ?).
  5. Rédiger l'algorithme de Echanger_Moities.
  6. Rédiger l'algorithme du programme principal orchestrant les trois transformations successives avec affichage à chaque étape.
  7. Traduire le tout en Python 3.
💡 Conseils méthodologiques & Indices
  • Dans Inverser_Miroir, si la boucle parcourait jusqu'à $n-1$, chaque élément serait permuté deux fois, restaurant ainsi le tableau d'origine !
  • Dans Rotation_Droite, décaler impérativement en marche arrière : Pour i de n - 1 à 1 (pas de -1) Faire t[i] ← t[i - 1]. Si l'on décalait vers l'avant, la première valeur écraserait toutes les suivantes.
  • Dans Echanger_Moities, le décalage pour la seconde moitié est $m = n \text{ Div } 2$. Échanger Permuter_Cases(t, i, i + m) pour $i$ allant de 0 à $m - 1$.
Jeux d'essais à vérifier : ($N = 6$)
• Tableau initial : $T = [1, 2, 3, 4, 5, 6]$
  1. Après Inverser_Miroir : $T = [6, 5, 4, 3, 2, 1]$
  2. Après Rotation_Droite : $T = [1, 6, 5, 4, 3, 2]$
  3. Après Echanger_Moities ($m = 3$) :
     $T[0..2] \leftrightarrow T[3..5] \implies T = [4, 3, 2, 1, 6, 5]$.

Exercice 7 : Bio-informatique & Analyse de Brin d'ADN (Mixte Filtrage & Compression)

🔴 Avancé

Dans une plateforme d'analyse génomique, un fragment de brin d'acide désoxyribonucléique (ADN) est représenté par un tableau de caractères $ADN$ de taille $N$ ($5 \le N \le 60$).

Chaque cellule du tableau représente un nucléotide élémentaire et doit impérativement être l'une des 4 bases azotées :

'A' : Adénine 'C' : Cytosine 'G' : Guanine 'T' : Thymine

Avant de stocker ou d'aligner le brin, le système doit calculer la composition nucléotidique, évaluer le ratio de stabilité thermique ($GC\%$), et générer une séquence compactée éliminant les nucléotides répétés consécutivement (ex: ['A','A','C','G','G','G','T'] $\to$ ['A','C','G','T']).

La conception impose les modules suivants :

  • Une procédure Saisie_Taille(@n : Entier) avec validation $5 \le N \le 60$.
  • Une fonction Est_Nucleotide(c : Caractère) : Booléen qui renvoie Vrai si $c \in \{'A', 'C', 'G', 'T'\}$ et Faux sinon.
  • Une procédure Remplir_ADN(@adn : TabCar, n : Entier) qui saisit chaque case avec une boucle Répéter ... Jusqu'à Est_Nucleotide(adn[i]) pour refuser toute saisie invalide.
  • Une procédure Compter_Bases(adn : TabCar, n : Entier, @nb_a : Entier, @nb_c : Entier, @nb_g : Entier, @nb_t : Entier) qui comptabilise les 4 fréquences en un unique parcours.
  • Une fonction Taux_GC(nb_c : Entier, nb_g : Entier, n : Entier) : Réel qui retourne le pourcentage de bases G et C : $\frac{nb\_c + nb\_g}{n} \times 100$.
  • Une procédure Compacter_Sequence(adn : TabCar, n : Entier, @compact : TabCar, @nb_comp : Entier) qui construit le tableau compact ne contenant aucun doublon consécutif et calcule sa taille effective nb_comp.
  • Une procédure Afficher_Sequence(t : TabCar, n : Entier, libelle : Chaîne) qui affiche les nucléotides accolés ou séparés par des tirets.
Travail demandé :
  1. Pourquoi la fonction Est_Nucleotide simplifie-t-elle considérablement le contrôle de saisie dans Remplir_ADN ?
  2. Dresser le T.D.N.T. pour TabCar = Tableau de 60 Caractère.
  3. Rédiger l'algorithme de Est_Nucleotide et de Remplir_ADN.
  4. Dresser le T.D.O.L. et rédiger l'algorithme de la procédure Compter_Bases.
  5. Rédiger l'algorithme de la fonction Taux_GC.
  6. Rédiger l'algorithme de la procédure Compacter_Sequence. Justifier l'algorithme utilisé pour insérer le premier élément puis tester chaque élément $i$ ($1 \le i < n$) par rapport à son prédécesseur $i-1$.
  7. Rédiger l'algorithme principal (avec son T.D.O.G.) et fournir l'implémentation Python 3 avec numpy.
💡 Conseils méthodologiques & Indices
  • Dans Compacter_Sequence : la première base est toujours conservée : compact[0] ← adn[0] et nb_comp ← 1. Pour $i$ allant de 1 à $n-1$, si adn[i] ≠ adn[i-1], on ajoute à compact[nb_comp] ← adn[i] et on incrémente nb_comp ← nb_comp + 1.
  • En Python, pour un tableau de caractères avec numpy, déclarer : adn = array([''] * 60) ou array([' '] * 60).
Jeux d'essais à vérifier : ($N = 10$)
• Séquence saisie : $ADN = ['A', 'A', 'C', 'G', 'G', 'G', 'T', 'T', 'C', 'A']$
  → Décompte : $A = 3$, $C = 2$, $G = 3$, $T = 2$
  → Taux GC : $\frac{2 + 3}{10} \times 100 = \mathbf{50.0\%}$
  → Séquence compactée : $Compact = ['A', 'C', 'G', 'T', 'C', 'A']$ (Taille effective $nb\_comp = 6$).

Exercice 8 : Fusion Ordonnée de Deux Tableaux & Analyse d'Audience (Mixte Algorithme d'Interclassement)

🔴 Avancé

Une plateforme internationale de diffusion vidéo en streaming héberge deux clusters de serveurs régionaux $S_1$ et $S_2$. Chaque serveur enregistre les identifiants numériques ($ID$) des abonnés actuellement connectés.

Chaque serveur maintient sa liste d'abonnés classée par ordre strictement croissant :

  • Serveur 1 : Tableau $T_1$ de taille $N_1$ ($2 \le N_1 \le 30$).
  • Serveur 2 : Tableau $T_2$ de taille $N_2$ ($2 \le N_2 \le 30$).

Pour consolider l'audience globale, l'administrateur souhaite :

  1. Saisir chaque tableau en imposant que chaque valeur saisie soit strictement supérieure à la précédente ($T[i] > T[i-1]$ pour $i \ge 1$).
  2. Fusionner les deux listes en un troisième tableau $T_3$ de taille $N_3 = N_1 + N_2$ trié par ordre croissant en un seul passage (algorithme d'interclassement linéaire sans aucun tri ultérieur !).
  3. Extraire dans un tableau communs les identifiants d'abonnés connectés simultanément sur les deux serveurs (détection des partages de comptes).

La structure modulaire requise est la suivante :

  • Une procédure Saisie_Taille(@n : Entier, num_serveur : Entier) pour valider $2 \le N \le 30$.
  • Une procédure Remplir_Croissant(@t : Tab, n : Entier) qui saisit la première case $t[0]$, puis pour chaque case $i$ ($1 \le i < n$), boucle jusqu'à ce que $t[i] > t[i-1]$.
  • Une procédure Fusionner(t1 : Tab, n1 : Entier, t2 : Tab, n2 : Entier, @t3 : TabGrand, @n3 : Entier) :
    • Utilise trois indices : $i$ (curseur sur $T_1$), $j$ (curseur sur $T_2$) et $k$ (curseur sur $T_3$).
    • Tant que $i < n_1$ et $j < n_2$, compare $t_1[i]$ et $t_2[j]$ et insère le plus petit dans $t_3[k]$.
    • Copie ensuite les éléments restants du tableau non encore épuisé.
    • Fixe $n_3 \leftarrow n_1 + n_2$.
  • Une procédure Trouver_Doublons(t1 : Tab, n1 : Entier, t2 : Tab, n2 : Entier, @communs : Tab, @nb_com : Entier) qui tire parti du tri croissant des deux tableaux pour identifier les valeurs communes en un seul parcours conjoint.
  • Une procédure Afficher_Liste(t : Tab, n : Entier, titre : Chaîne) pour afficher les éléments d'un tableau.
Travail demandé :
  1. Pourquoi l'algorithme d'interclassement (fusion) est-il beaucoup plus performant que la concaténation brute des deux tableaux suivie d'un algorithme de tri (comme le tri à bulles ou par sélection) ? Préciser la complexité de cet algorithme.
  2. Dresser le T.D.N.T. global en déclarant Tab = Tableau de 30 Entier et TabGrand = Tableau de 60 Entier.
  3. Rédiger l'algorithme de Remplir_Croissant en explicitant la boucle de contrôle d'ordre strict.
  4. Dresser le T.D.O.L. et rédiger l'algorithme complet de la procédure Fusionner.
  5. Rédiger l'algorithme de la procédure Trouver_Doublons.
  6. Dresser le T.D.O.G. et rédiger l'algorithme du programme principal.
  7. Donner le code source complet en Python 3 avec numpy.
💡 Conseils méthodologiques & Indices
  • Structure classique de l'interclassement : 
    i ← 0 ; j ← 0 ; k ← 0
TantQue (i < n1) Et (j < n2) Faire
  Si t1[i] ≤ t2[j] Alors
    t3[k] ← t1[i] ; i ← i + 1
  Sinon
    t3[k] ← t2[j] ; j ← j + 1
  Fin Si
  k ← k + 1
Fin TantQue
TantQue i < n1 Faire
  t3[k] ← t1[i] ; i ← i + 1 ; k ← k + 1
Fin TantQue
TantQue j < n2 Faire
  t3[k] ← t2[j] ; j ← j + 1 ; k ← k + 1
Fin TantQue
  • Pour Trouver_Doublons : si $t_1[i] = t_2[j]$, mémoriser dans communs et avancer les deux curseurs $i$ et $j$. Si $t_1[i] < t_2[j]$, avancer $i$ ; sinon avancer $j$.
Jeux d'essais à vérifier :
• Serveur 1 ($N_1 = 4$) : $T_1 = [102, 108, 115, 120]$
• Serveur 2 ($N_2 = 5$) : $T_2 = [105, 108, 112, 120, 130]$
  → Fusion ordonnée $T_3$ ($N_3 = 9$) :
     $[102, 105, 108, 108, 112, 115, 120, 120, 130]$
  → Utilisateurs communs ($nb\_com = 2$) :
     communs = [108, 120].
